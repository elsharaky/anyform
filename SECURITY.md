# Security Policy

## Reporting a vulnerability

Please **do not** report security vulnerabilities through public GitHub issues,
pull requests, or discussions.

Instead, please email the maintainer (the owner of the repository) directly or
use GitHub's [private security advisories](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)
feature, which reports the issue privately to the maintainers.

Please include:

- A description of the vulnerability.
- The affected version(s) and, if possible, the vulnerable code path.
- A minimal reproduction, if available.

We aim to respond to security reports within **7 days**.

## Supported versions

| Version | Supported |
|---------|-----------|
| Latest release | ✅ |
| Previous minor | ⚠️ on a best-effort basis |
| Unreleased (`main`) | ⚠️ use at your own risk |

## Disclosure

Once a fix is available, we will publish a release and coordinate disclosure so
users can upgrade before details are made public.
